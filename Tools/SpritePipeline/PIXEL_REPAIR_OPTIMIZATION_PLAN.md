# 逐帧修补优化计划

## 目标

把“逐帧修补”从单张 PNG 修改器推进为面向动画连续性的安全工作台。它必须同时帮助用户判断动作是否接得上、位置是否连续、角色身份是否稳定，并保证任何辅助显示都不会污染最终资产。

始终成立的约束：

- 单帧保持项目合同规定的固定 RGBA 画布；当前赛博角色为 128×128。
- 不自动裁边、扩框、缩放、重采样或逐帧居中。
- 允许动作产生自然连续位移，只阻止或提醒突变式位移。
- 所有像素修改必须由用户明确执行，使用整数坐标，并可撤销。
- 原始 v0 永久只读；草稿、手工版本和外部/AI 版本分别记录。
- 手工修改不消耗生成额度；外部/AI 修补仍受每帧两轮限制。

## 当前里程碑：无损内核与连续性工具

状态：功能已实现；自动化回归由统一测试入口覆盖，真实浏览器烟测仍待执行，不能用单元或集成测试代替。

- 精确 RGBA 铅笔、可清除原始帧和新增笔画的透明黑色橡皮擦，以及直接读取像素的吸管；橡皮擦模式临时隐藏洋葱皮，避免相邻帧残影造成擦除失败的错觉。
- 1×1、2×2、3×3 方形笔刷，整数倍率缩放、平移、网格和高分屏坐标换算。
- 正反方向一致的连续像素画线。
- 四方向、RGBA 完全匹配的精确填充。
- 矩形框选、可见角色范围选择、方向键 1 像素和 Shift+方向键 8 像素移动。
- 选区越过固定画布时整体阻止，不静默裁切。
- 上一帧洋红、下一帧青色的画布内洋葱皮；循环动作按真实播放顺序首尾相接。
- 当前角色范围和“前帧→当前→后帧”质心位移显示；只提供参考，不自动对齐。
- 一次操作一个撤销步骤、100 步历史、实时变化像素数量与包围盒。
- 保存期间冻结像素写操作；基础 SHA-256 阻止双窗口覆盖。
- 正式版本与自动 QA 分阶段反馈；QA 异常不能把已保存版本误报成丢失。
- 画布保存后通知外层页面刷新播放检查与修补列表。
- 本机草稿具有数量和容量上限，避免长期使用耗尽浏览器存储。
- 草稿同时保存基础 RGBA 与修改后 RGBA；基础版本变化时进行“基础／草稿／当前版本”三方合并，只自动合并互不冲突的像素，并在恢复决定完成前禁止继续改图。
- 每个页面实例使用独立草稿键；刷新、复制标签页和多窗口不会共享同一个活动草稿槽，也不会由较晚关闭的旧页面覆盖新页面草稿。
- 外部 PNG 替换绑定选择文件时的任务、候选、帧和基础 SHA-256；切换上下文或刷新修补投影会清空旧上传，防止把 A 帧文件写进 B 帧。
- 每次成功 QA 记录算法版本；旧算法批准但尚未导出的候选允许重新检查并重新审批，已导出候选保持不可变。导出配方与 QA 报告同时记录版本。
- 原始 provider 清单、提交标记和原始 PNG 是复检、批准与导出的服务层硬门槛；修补后的 active 版本可不同，但不能掩盖已付费原始结果损坏。重复扫描同一个持久错误不会持续增加任务历史。

## 第二里程碑：修补工作流与时间轴

优先级：最高。

1. `[已实现]` 修补页显示候选的完整帧时间轴，不再只显示“待修补帧”下拉框。
2. `[已实现]` 时间轴区分未检查、已通过、待修补、已修改、仍有阻止问题五种状态。
3. `[已实现]` 支持上一问题帧、下一问题帧；切换或刷新时未提交像素由分帧、分页面草稿保存，恢复决定完成前禁止编辑。
4. `[部分实现]` 已有“仅当前帧”和前后洋葱皮；“修改前后闪烁”仍待实现。
5. `[已实现]` 保存后在同一页展示本次 QA 变化：已解决、新出现、仍存在；QA 中途失败时保留上一次成功基线，重试成功后再生成摘要。
6. `[部分实现]` 已显示相邻帧质心位移；速度变化的专门可视化仍待实现，并且不会提供“一键自动居中”。
7. `[部分实现]` 保存、复查和外部替换后保持当前任务、候选与帧上下文；修补完成后可直接返回整段动画并从头重播，精确保持原播放位置仍待实现。
8. `[待实现]` 把六类 QA 预览发布为不可变版本包，再原子切换任务指针。当前单个预览文件自身采用原子替换，不会出现半张图片，但并发刷新或进程中断时仍可能短暂缺图；这只影响可重建预览，不影响原始帧、修补版本或导出门禁。

补充完成项：循环动作的第一帧和末帧会把另一端作为真实上一／下一邻帧，时间轴、洋葱皮和邻帧预览使用同一播放顺序；两帧循环不会重复叠加同一邻帧。手工像素编辑权限已与逐帧审核标签解耦：任意非终态、未导出的候选帧均可直接修改并在保存后回到待复审状态；外部整帧替换仍要求显式标记待修补。对于误标或实际可用的问题帧，修补页可直接采用原帧并前进；全部问题帧处理后可回到整段播放检查，最终确认会自动填充导出页。

退出条件：用户能够连续处理多个问题帧，不需要手工刷新，也不会因切换页面丢失草稿或上下文。

## 第三里程碑：专业区域与像素工具

优先级：高。

- 选区复制、剪切、粘贴；粘贴始终落在整数像素坐标。
- 非矩形透明选区蒙版，以及选区反选和按颜色选择。
- 直线、矩形轮廓、矩形填充、水平/垂直翻转。
- 可选的项目色板面板、最近颜色和颜色替换预览。
- 色板保护默认只提醒，不擅自量化颜色。
- 显示越界预览；只有用户明确选择时才允许裁切，而且默认仍为阻止。
- 历史记录增加工具名、变化像素数和范围，便于定位误操作。

退出条件：常见武器断裂、轮廓毛刺、局部错色和单帧小幅错位可以在本机完成，不依赖外部绘图软件。

## 第四里程碑：AI 遮罩修补

优先级：在人工工具稳定后进行。

1. 复用人工选区生成明确的二值修补遮罩。
2. 请求前同时展示当前帧、前一帧、后一帧、角色原型、遮罩和最终提示词。
3. 先显示额度估算，再由用户明确点击提交；禁止自动重试或重复扣费。
4. PixelLab 动画编辑优先传入带上下文的短序列；GPT 图像编辑使用角色原型、相邻帧、坏帧和遮罩。
5. 返回结果只提取目标帧，不替换邻帧；尺寸和 Alpha 不符立即拒绝。
6. 新结果作为独立候选版本预览，用户确认后才成为 active_path。
7. 每帧最多两轮外部/AI 修补，手工版本不占用次数。

退出条件：服务中断、页面刷新、未知提交结果和 QA 失败都不会导致重复扣费、结果丢失或静默覆盖。

## 第五里程碑：游戏工程验收

- 对 16 帧、4×4、512×512 新 Sheet 做 Godot 导入与 Nearest 采样验证。
- 为旧低帧数动作提供显式迁移报告，不猜测旧工程的帧索引。
- 检查攻击、跳跃等关键帧索引与代码冻结帧是否同步。
- 检查空中攻击播放 FPS、受击循环和向后闪避状态机接线。
- 用实际场景验证脚底轨迹、武器伸展、碰撞时机和循环首尾。

退出条件：导出资产在真实游戏中播放、切换和触发正确，而不仅是在工具预览中看起来正确。

## 测试门禁

每次合并至少运行：

- Python 服务、REST、CLI、版本和 QA 测试。
- Node 像素算法测试；已通过统一 pytest 入口自动调用。
- 本机真实浏览器烟雾测试：载入、缩放、指定像素绘制、撤销、重做、保存、重载并逐字节核对。当前仍待执行，不得以 Python/Node 自动化测试结果代替。
- DPR 1、1.25、1.5、2 的坐标映射测试。
- 洋葱皮、网格、选区、光标和参考线不得改变 dirty 状态或最终 PNG。
- 编辑目标帧后，所有兄弟帧的路径、SHA-256 和字节保持不变。

统一验证命令：`python -m pytest -q`。
